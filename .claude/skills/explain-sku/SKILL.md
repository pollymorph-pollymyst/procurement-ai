# Разобрать один артикул

1. Получи расчёт по артикулу (номер вида `SKU-XXXXXX`):
   ```bash
   PYTHONIOENCODING=utf-8 python -m procurement sku SKU-XXXXXX
   ```
   Нет расчёта — сначала `python -m procurement run --no-open`.

2. Объясни закупщику по цепочке, используя только числа из вывода:
   - **сколько продаётся**: `demand_3m`, `demand_12m`, пик сезона `season_peak`;
   - **что есть**: остаток `on_hand`, в пути `pipeline` (сомнительные `doubtful` не считаются);
   - **на сколько хватит**: `cover_until` / `cover_days`;
   - **почему сейчас**: срок поставки `lead_days`, дата заказа `order_date`, приход `arrival_date`;
   - **почему столько**: `qty` покрывает спрос до следующего прихода (цикл `cycle_days`) плюс
     страховой запас `safety_stock`, округлено до шага `round_step`; хватит до `cover_after`;
   - **риски**: `deficit` (не успеем довезти, упустим `lost_units`), `excess_qty`, `flags`, `markup`.
   Готовое объяснение одной фразой — в поле `reason`.

3. Пиши как коллеге-закупщику: 5–8 коротких строк, без слов «модель», «SKU-уровень», «алгоритм».
   Термины — из `GLOSSARY.md`. Если пользователь не согласен с цифрой — подскажи, какую настройку
   в `config.toml` это меняет (например, `страховой_запас_макс_доля`, уровни сервиса A/B/C).
