# Планирование закупок

Система для импортёра электроинструмента, садовой техники и сантехники из Китая (поставка 4–6 месяцев).
По выгрузке из ERP каждый день отвечает на пять вопросов:

1. **что** заказать;
2. **сколько** заказать;
3. **на сколько хватит** текущего запаса с учётом заказов в пути;
4. **когда** размещать следующий заказ;
5. где **риск дефицита или избытка**.

Ответ — дашборд (первый экран: что заказать сегодня и у кого) и готовые Excel-заказы по каждому поставщику.

**Дашборд:** `docs/index.html` (онлайн — ссылка GitHub Pages после публикации).

---

## Как запустить за 2 минуты (Windows)

1. Дважды щёлкните **«Открыть закупки.bat»**.
2. При первом запуске откроется настройка из трёх шагов:
   - **Комментарий** — кто будет писать «Комментарий аналитика» (см. ниже) или «Пропустить — писать по шаблону»;
   - **Данные** — где лежат выгрузки (по умолчанию папка «Входящие»). Программа покажет, какие таблицы
     нашлись, и попросит указать, что в нераспознанных файлах. На этом шаге файлы только читаются.
     Если папка пуста, можно начать на выгрузке, которая уже лежит в проекте (13.08.2026);
   - **Первый расчёт** — включить ли обновление по расписанию и нажать «Посчитать».

   Пройти настройку заново: «Управление» → «Данные» → «Пройти первую настройку заново».
3. Откроется дашборд. Нажмите **«Скачать заказ (Excel)»** у нужного поставщика или **«Скачать все заказы»**.
   Когда заказ ушёл поставщику — нажмите **«Отправлено»**: до следующей выгрузки он считается заказом в пути
   и второй раз не предлагается.

Первый запуск ставит нужные библиотеки сам (1–2 минуты). Если на компьютере нет Python 3.11+,
файл подскажет, откуда его скачать. Дальше каждый запуск занимает около 10 секунд.

| Файл | Что делает |
|---|---|
| **Открыть закупки.bat** | открывает дашборд с панелью «Управление»: обновить, расписание, правила расчёта, праздники, откуда берутся данные |
| **Обновить анализ.bat** | берёт выгрузку из папки, пересчитывает, открывает дашборд |
| **Включить ежедневный запуск.bat** | пересчёт каждый день в 08:00 (Планировщик Windows). С параметром `off` — выключить |
| **Собрать архив для отправки.bat** | zip проекта в `dist/` без лишних файлов |

Файлы заказов: `docs/orders/` (по поставщику и общий `vse_zakazy_*.xlsx` со всеми списками).
Все настройки меняются в дашборде: **«Управление»** (кнопка справа вверху). Они хранятся в `config.toml`
на русском, с пояснениями — его можно править и руками.

## Откуда берутся данные

Подходит выгрузка из 1С, другой учётной системы или Excel: файлы **xlsx или csv** (можно в zip-архиве),
любая кодировка и разделитель, со строками заголовка отчёта сверху. Нужны продажи, остатки и справочник
товаров; заказы поставщикам, поступления и поставщики — желательно (без них часть выводов не строится).

- **Колонки распознаются по названиям** («Номенклатура», «Код», «Количество», «Период», «Склад»…).
  Если файл не распознан, на дашборде появится плашка «Файл … не распознан» — один раз укажите,
  что в нём и что значат колонки. Дальше файлы такого вида берутся сами.
- **Неполная выгрузка не испортит план.** Если в новом файле заметно меньше товаров, чем в прошлый раз
  (например, остатки одного склада), или артикулы не из справочника, обновление останавливается: на дашборде
  остаются прошлые данные и объяснение, что не так. Если файл правильный — кнопка «Взять как есть».
- **Можно присылать только свежий месяц.** Продажи и остатки из нового файла ложатся поверх прошлой
  истории: заменяются только те месяцы, что есть в файле.
- **Дата выгрузки** берётся из имени файла («остатки 13.08.2026.xlsx» или «…2026-08-13…»). Если даты
  в имени нет — из даты файла, а если файл явно скопирован позже (на неделю позже последнего месяца
  в данных) — на конец последнего месяца. Откуда взята дата, видно в «Откуда берутся данные».
- **Файл заказа поставщику** — только то, что нужно ему: артикул, товар, бренд, количество, кратность,
  пометка «Срочно» и дата, к которой товар нужен (в шапке — срок поставки с праздниками). Остатки,
  «почему» и прочие внутренние данные — только в общем файле «Скачать все заказы».
- **Выключатель автообновления — про этот компьютер.** Облачное расписание (`.github/workflows/daily.yml`)
  он не трогает; меняется только время, когда автообновление включено.
- **Папку можно поменять:** «Управление» → «Откуда берутся данные» → «Выбрать другую папку».
  Удобно указать сетевую папку, куда 1С выкладывает отчёты.
- **Без ручной работы в 1С:** администратор настраивает стандартную **«Рассылку отчётов»** (продажи,
  остатки, заказы поставщикам) в эту папку по расписанию, а в дашборде включается автообновление.
- **Следующий шаг — прямое подключение к 1С** через OData (стандартный REST-интерфейс 1С:Предприятия):
  программа сама забирает регистры продаж, остатков и заказов, без файлов. Нужны публикация базы
  на веб-сервере и пользователь с правами на чтение. В этой версии не сделано.

Что пришло при последнем обновлении (какие файлы, сколько строк, за какой период) — там же, в «Откуда берутся данные».

## Кто пишет «Комментарий аналитика»

Выбирается при первом запуске, меняется в «Управление» → «Комментарий аналитика». Кнопка «Проверить связь»
проверяет ключ и адрес до сохранения.

| Вариант | Что нужно | Когда подходит |
|---|---|---|
| **Claude (Anthropic)** | ключ с console.anthropic.com | лучший текст; сервис зарубежный |
| **ChatGPT, DeepSeek, YandexGPT, OpenRouter** и любой OpenAI-совместимый | адрес (подставляется), версия, ключ | уже есть договор с одним из них |
| **GigaChat (Сбер)** | ключ авторизации с developers.sber.ru, сертификат Минцифры (gosuslugi.ru/crt) | данные остаются в России |
| **На этом компьютере** — Ollama, LM Studio | установленная и запущенная программа | данные не уходят с компьютера |
| **Без внешнего сервиса** | ничего | текст по шаблону, работает всегда |

Ключи хранятся только в `.env` на этом компьютере: не попадают в `config.toml`, дашборд, архив для отправки
и git. Если сервис не ответил или написал число не из расчёта, комментарий собирается по шаблону,
а в «Управлении» видно почему. В GitHub Actions ключ задаётся секретом репозитория: `ANTHROPIC_API_KEY`, `OPENAI_API_KEY` или `GIGACHAT_AUTH_KEY`.
Если сервис в дашборде не выбран, берётся первый, для которого есть ключ (для ChatGPT-совместимых нужны ещё
`адрес` и `модель` в `config.toml`).

## Регулярный запуск

- **По запросу:** «Обновить анализ.bat» или в Claude Code: «обнови анализ» (скилл `plan-purchases`).
- **Каждый день на компьютере:** «Включить ежедневный запуск.bat».
- **Каждый день в облаке:** GitHub Actions (`.github/workflows/daily.yml`) в 07:00 МСК пересчитывает
  и публикует дашборд на GitHub Pages. Новая выгрузка — загрузить zip в папку «Входящие» прямо на GitHub
  (Add file → Upload files): анализ пересчитается сам.

Каждый запуск сохраняет снимок в `outputs/history/`, и вкладка **«Что изменилось»** показывает разницу
с прошлым разом: какие товары стали срочными, у кого поменялось количество, как сдвинулись итоги.

## Как считаем (коротко)

- **Спрос, а не продажи.** Месяцы, когда товара не было на складе, не используются: продажи там занижены.
- **Прогноз** = уровень спроса за последний год (свежие месяцы весят больше) × сезонность категории
  × половина годового тренда. Проверка на прошлом году: ошибка 101% против 125% у «среднего за год».
- **Дневная симуляция** запаса на 18 месяцев: остаток + заказы в пути (просроченные > 60 дней не верим)
  − прогноз. Заказ нужен, когда запас к моменту прихода опустится ниже страхового.
- **Заказы в пути** считаются с поправкой на недовоз: если поставщик обычно довозит, скажем, 80% заказанного,
  то и от открытого заказа ждём 80% (нужно ≥ 3 закрытых заказов; не ниже 30%). Отключается в «Управлении».
- **Праздники у поставщиков.** Китайский Новый год, Золотая неделя, Дивали, Холи, Курбан-байрам, новогодние
  каникулы: если простой фабрик попадает между заказом и приходом, срок поставки удлиняется на эти дни,
  и заказ предлагается раньше. Страна назначается по типу поставки (импорт — Китай, местный — Россия)
  или отдельно поставщику; праздники и дни простоя включаются и меняются в «Управлении».
- **Отправленные заказы.** Кнопка «Отправлено» у поставщика: при пересчёте этот заказ идёт в запас как
  «в пути», пока он не появится в следующей выгрузке. Если нажали по ошибке — «Не отправляли — убрать».
- **Количество** покрывает спрос до следующего прихода (цикл заказа поставщика 30–90 дней)
  + страховой запас (A 95%, B 90%, C 85%), округлено до шага из истории заказов.
- **Риски:** «не успеем довезти» (кончится раньше, чем придёт заказ, размещённый сегодня; если заказ уже в пути — до его прихода), избыток (> 12 мес. запаса),
  мёртвый остаток, низкая наценка (< 25%, не заказываем автоматически), нет поставщика, редкий спрос.
- **Комментарий аналитика** — короткий текст над заказами. Расчёт от него не зависит. Каждое число
  в тексте автоматически сверяется с расчётом — выдуманные цифры не пройдут, вместо них будет текст по шаблону.

Подробно — вкладка «Как считаем» на дашборде. Термины — `GLOSSARY.md`.

## Устройство

```
Обновить анализ.bat         ← точка входа для пользователя
Входящие/                   ← сюда кладут выгрузку
config.toml                 ← настройки на русском
procurement/                ← расчёт (Python: pandas, numpy, openpyxl)
  sources.py                ← приём выгрузок: xlsx/csv/zip, распознавание колонок, сопоставление
  data.py  forecast.py  plan.py  pipeline.py  backtest.py
  holidays.py               ← праздники у поставщиков → удлинение срока поставки
  server.py  control.py  settings.py  schedule.py   ← панель «Управление» (локальный сервер)
  writers.py                ← кто пишет комментарий: Claude, OpenAI-совместимые, GigaChat, локальные
  history.py  commentary.py  export.py  build.py  __main__.py
dashboard/index.html        ← шаблон дашборда (один файл, без фреймворков)
docs/                       ← готовый дашборд и Excel-заказы (GitHub Pages)
prompts/analyst.md          ← промпт «Комментария аналитика»
tests/                      ← проверки (pytest)
CLAUDE.md                   ← инструкции для Claude Code
.claude/skills/             ← plan-purchases (обновить анализ с комментарием), explain-sku (разобрать артикул)
GLOSSARY.md  PRODUCT.md  DESIGN.md  GATES.md
```

Команды для разработчика:

```bash
pip install -r requirements-dev.txt  # библиотеки + pytest
python -m procurement serve          # дашборд с панелью «Управление» (как «Открыть закупки.bat»)
python -m procurement run            # полный расчёт и дашборд
python -m procurement check          # проверить данные, показать итоги
python -m procurement sku SKU-F4FE31 # расчёт по одному артикулу
python -m procurement comment        # вставить комментарий из Claude Code без пересчёта
python -m pytest -q                  # тесты
```
