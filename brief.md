# Бриф: ИИ-система планирования закупок (тестовое задание)

## Задача заказчика (дословно по сути)
Импортёр электроинструмента, садовой техники и сантехники из Китая. Срок поставки 4–6 месяцев.
Каждый месяц закупщики решают, что и сколько заказать, чтобы покрыть спрос и не забить склад.
Нужна ИИ-система, которая по данным определяет:
1. какие товары закупить;
2. сколько заказать;
3. на какой срок хватит текущего запаса с учётом заказов в пути;
4. когда размещать следующий заказ;
5. по каким позициям риск дефицита или избытка.

Сдать через 48 часов в Telegram:
- **ссылку на дашборд** — по нему видна полная картина закупок и можно принять решение: что, сколько, когда;
- **видео**, где видно устройство решения: Claude Code, структура проекта, CLAUDE.md, скиллы, промпты;
- **регулярный запуск**: ежедневно или по запросу, при обновлении данных — свежие рекомендации и что изменилось с прошлого раза.

## Главный принцип для пользователя
Пользователь — обычный закупщик, вникать в устройство системы не хочет.
- **Минимум кликов.** На первом экране сразу «что сделать сегодня»: список к заказу, сгруппированный по поставщикам, и одна кнопка «скачать заказ» (Excel/CSV).
- Простой русский язык без жаргона («хватит до 12 декабря», а не «DoC = 121»). Методика есть, но спрятана в раскрывающийся блок.
- Запуск одним действием: двойной клик по `Обновить анализ.bat` (Windows) или `/plan-purchases` в Claude Code. Для новой выгрузки — положить файлы в `data/raw/` и запустить.
- Проработать мелочи: пустые состояния, неполные данные, понятные ошибки («нет файла sales_monthly.csv — положите выгрузку в data/raw»), мобильная ширина, тёмная тема.

## Принятые решения
- Данные: **файлы заказчика** (уже распакованы в `data/raw/`, описание — `data/raw/README.md`).
- Дашборд: **статический HTML**. На GitHub **не публикуем**: проект сдаётся архивом в личку рекрутеру. Способ дать ссылку решается отдельно (см. раунд 2).
- **Раунд 2:** публикуем всё-таки через GitHub (Pages + Actions), но **с отдельного аккаунта** (не основного). Вход в него пользователь делает сам перед публикацией; публикация только после его «публикуй». Автозапуск: GitHub Actions (основной), задача в Claude и Планировщик Windows (запасные). Ключа API нет — комментарий по шаблону, если ключа нет. Python ставится/проверяется батником сам.
- Пользователь может быть совсем не знаком с ИИ: никаких терминов «LLM», «промпт», «модель» в интерфейсе. ИИ на дашборде — это просто «Комментарий аналитика».
- Решения раунда 1 приняты по рекомендациям: дата анализа = дата данных; цикл заказа по поставщику (30–90 дн.); сервис A95/B90/C85; заказы в пути с просрочкой >60 дн. не учитываются и помечаются; низкая наценка и «нужен поставщик» — отдельные списки вне файла заказа; избыток >12 мес; округление до шага из истории; загрузка через папку `Входящие` + двойной клик; русские названия категорий; первый экран — вывод, 4 цифры, заказы по поставщикам с кнопкой Excel.
- ИИ-слой: **оба варианта**.
  - Claude Code: скилл `/plan-purchases` запускает расчёт, читает сводку, пишет комментарий закупщику и пересобирает дашборд.
  - Python + API выбранного сервиса (Claude, ChatGPT-совместимые — DeepSeek, YandexGPT, OpenRouter, GigaChat, Ollama/LM Studio; у каждого своя версия по умолчанию): для запуска по расписанию без Claude Code (GitHub Actions cron / Планировщик Windows). Без API-ключа — резервный комментарий по правилам, дашборд строится всегда.
- Числа считает детерминированный Python (pandas/numpy). LLM только объясняет и приоритизирует, цифры не придумывает.
- Один общий промпт аналитика в `prompts/` для обоих режимов.

## Данные (проверено)
- 791 SKU, 6 категорий; 413 продавались за последние 12 мес, 378 — мёртвый ассортимент.
- Продажи помесячно за 2020-11…2026-08; 2026-08 неполный (по 13-е) — **дата анализа 2026-08-13**.
- Остатки на 1-е число с 2024-01. **Нет строки = остаток 0** (нулевых строк в файле нет). Месяц с нулевым остатком = упущенный спрос, в обучение как «спроса нет» не брать.
- Баланс: остаток[след] ≈ остаток + приходы − продажи + возвраты.
- Заказы в пути: 57 open, 20 039 шт. pending, из них 17 127 с датой прихода в будущем. Есть просроченные (PO-1A9C1A опоздал почти на год, PO-A4A6FF — на 3 мес). Часть уже пришла (приходы 2026-08-01 по PO-C979A7), а pending не уменьшен — не посчитать дважды.
- Поставщики довезли 39% заказанного по закрытым заказам — показать надёжность, учитывать риск.
- Плечо: медиана 123 дня, p90 205, верхняя граница 180.
- Сезонность разная: space_heaters — пик в октябре (42% года), string_trimmers и trimmer_blades — май, sanitary_faucets — ровно.
- Порог наценки `MIN_MARKUP_PCT = 25`: ниже порога в автозаказ не идёт, а попадает в список «пересмотреть цену/вывести» (68 SKU).
- 153 SKU без поставщика/приходов (`supply_type = unknown`).
- Денег в данных нет: только наценка % и дециль цены.

## Методика (предложение)
- Спрос: очистка от дефицитных месяцев; сезонный индекс категории (отношение к скользящему среднему) с подтяжкой к индексу SKU при длинной истории; уровень = Σпродаж/Σиндексов за 12 мес; затухающий тренд год к году.
- Страховой запас: z по ABC (95/90/85%), разброс по остаткам прогноза, окно защиты = плечо + 30 дней (месячный цикл).
- Дневная проекция остатка: остаток + приходы по датам − прогноз → «запаса хватит до», дата точки заказа (когда остаток упадёт ниже страхового минус плечо), количество = довести до страхового запаса на момент следующего прихода, округлить до типичной партии из истории.
- Статусы: заказать сейчас / заказать в ближайшие 30 дней / заказ позже (дата) / запас в норме / избыток / пересмотр цены / мёртвый остаток / мало истории / нет поставщика.
- Бэктест прогноза (as-of год назад → факт), сравнение с наивным «средним за месяц» — показать, что сезонность учтена.
- История запусков в `outputs/history/`, сравнение с прошлым запуском: «что изменилось».

## Состав дашборда
1. Что сделать сегодня: ключевые цифры + комментарий ИИ.
2. Заказы к размещению по поставщикам с кнопкой выгрузки.
3. Календарь закупок на 12 мес: когда и сколько заказывать.
4. Риски: дефицит (не успеем довезти), избыток, просроченные поставки, низкая наценка, мёртвый остаток.
5. Все товары: фильтры, поиск, карточка SKU с графиком (история, прогноз, остаток с заказом и без, приходы).
6. Что изменилось с прошлого запуска.
7. Качество прогноза и сезонность; надёжность поставщиков.
8. Как это работает (свёрнуто).
